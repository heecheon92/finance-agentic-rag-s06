# 6회차 실습 — 평가 분석 · 3단계 비교 · ROI

수업은 지난 시간과 같이 "강사가 짧게 보여 주고 → 여러분이 직접 채우고 → 테스트로 확인"입니다. 오늘은 새 코드가 거의 없습니다. 채우는 자리가 둘(**실습 1** 지표 집계, **실습 2** judge 일치도)이고, 나머지는 지난 세 회차에 쌓인 결과 파일(`baseline.json` · `hybrid.json` · `agentic.json`)을 **같은 자로 다시 재서 읽는** 시간입니다. 결과물은 `results/compare.csv` · `judge.json` · `calc_e2e.json` 과 `docs/roi.md`(과제)입니다. 아래는 수업 순서대로 적은 것입니다.

**이 문서에서 쓰는 명령**

| 명령 | 하는 일 |
|---|---|
| `make test` | 자동 채점. 2~5회차 검사 102개와 오늘 검사 14개를 한 번에 돌려서 맞으면 초록, 틀리면 빨강 |
| `make compare` | 결과 파일 셋의 행을 다시 집계해 3단계 표를 찍고 `results/compare.csv` 로 저장한다. 실습 1 을 채우기 전에는 `NotImplementedError` |
| `make judge-calibrate` | 강사 답변 17개(20문항 중 답한 것)를 LLM-as-Judge 로 채점해 강사 라벨과 일치도를 잰다. 1~2분 |
| `make judge` | 자기 `agentic.json` 의 20문항 답변을 같은 judge 로 채점한다. `results/judge.json`. 1~2분 |
| `make calc-e2e` | 계산 골든셋 15문항을 에이전트에 넣어 검색 → 추출 → 계산까지 지나온 값을 기대값과 비교한다. 약 5분이라 휴식에 돌린다 |
| `make filter-accuracy` | Self-Query 가 뽑은 필터를 골든셋의 기대 필터와 필드별로 맞춰 본다. 1초 |
| `make roi` | `agentic.json` 의 토큰을 돈으로 바꾸고, 가정값으로 월 비용 · 3년 TCO · 절감을 찍는다. 1초 |
| `make check-s06` | 오늘 결과물이 조건 5개를 만족하는지 검사한다. 과제 확인도 이 명령으로 |

Windows 는 [install.md](../install.md) 의 PowerShell 명령을 씁니다. `make judge` 는 `.venv\Scripts\python scripts\judge_run.py` 입니다.

## 오늘 끝내고 갈 것

1. 결과 파일 셋을 **같은 자**(집계 함수 하나)로 다시 재서 한 표에 놓습니다. 유형별로 어디가 올랐고 어디가 내려갔는지 세 줄로 씁니다.
2. 답변의 품질을 **LLM-as-Judge** 로 채점하고, 그 judge 가 사람과 얼마나 맞는지부터 잽니다. 일치도를 재지 않은 judge 점수는 숫자처럼 보이는 의견입니다.
3. 계산 정확도 · 미답변과 오거절 · 적대적 · 필터 정확도 · 인제스천 게이트를 **숫자로** 만들고, 마지막에 **돈**으로 바꿉니다(ROI 1쪽).

## 1부 · 같은 자로 잰다

노트북 `notebooks/s06_eval.ipynb` 셀 1~2. 셀 번호는 코드 셀 첫 줄의 `# [셀 N]` 표시입니다. 이 노트북은 Qdrant 를 열지 않으므로 터미널과 같이 써도 됩니다.

3회차부터 하네스(`eval/harness.py`)는 하나였고 파이프라인만 갈아 끼웠습니다. 같은 40문항, 같은 gold 청크 ID, 같은 시계. 그래서 세 숫자가 한 표에 들어갑니다. 오늘은 파일에 적힌 요약(`overall` · `by_type`)을 믿지 않고 **행(`rows`)에서 다시 집계**합니다. 세 파일이 다른 날, 다른 코드로 만들어졌어도 자는 하나여야 합니다. 그 자가 실습 1 입니다.

지표 다섯의 분모가 다릅니다.

| 지표 | 분자 / 분모 |
|---|---|
| Recall@5 | 상위 5개 안에 gold 가 있는 문항 / 40 |
| MRR | 첫 gold 의 1/순위 평균 / 40 |
| 답변률 | 거절하지 않은 문항 / 40 |
| **오거절률** | 거절한 문항 / **답할 수 있는 38** |
| **미답변 정확도** | 거절했거나 "근거 부족" 판정으로 한계를 밝힌 문항 / **거절해야 할 2** |

오거절률과 미답변 정확도는 분모가 다릅니다. 한 숫자로 합치면 "전부 거절"이 좋은 점수를 받습니다.

## 실습 1 · `metrics.aggregate`

`src/finrag/eval/metrics.py` 의 `aggregate` 를 채웁니다. 25줄 안팎입니다.

**먼저 읽을 것.** 함수의 독스트링(블록에 들어가는 것과 언제 넣는지), 같은 파일의 `recall_at_k` · `mrr`, `results/agentic.json` 의 `overall` 하나(만들어야 할 모양이 그대로 있습니다), 그리고 `tests/test_metrics.py` 의 테스트 8개. 테스트가 곧 요구사항입니다.

**요구사항.** 테스트 8개가 보는 것입니다.

1. `overall` 은 전체 행으로, `by_type` 은 `type` 별로 같은 블록을 만듭니다. 블록에는 `recall@k`(ks 마다) · `mrr` · `n` 이 항상 들어갑니다. 소수 4자리.
2. `answer_rate` 는 `answered` 키가 있는 행이 하나라도 있을 때만 넣습니다. baseline · hybrid 행에는 `answered` 가 없으므로 그 파일에는 답변 지표 자리가 없어야 합니다(0 이 아닙니다).
3. `false_refusal_rate` 의 분모는 `answerable=True` 인 행입니다. 미답변형은 분모에 들어가지 않습니다. 그런 행이 없으면 키를 넣지 않습니다.
4. `abstain_accuracy` 의 분모는 `answerable=False` 인 행, 분자는 거절했거나 `grade == "insufficient"` 인 행입니다(한계를 밝힌 답변은 숫자를 안 만든 것이므로 정답). 그런 행이 없으면 키를 넣지 않습니다.
5. `latency_ms_avg` 와 `latency_ms_p95`. p95 는 정렬한 뒤 `int(n × 0.95) − 1` 번째(0 미만이면 0)입니다.
6. 마지막 테스트는 저장된 `results/agentic.json` 의 `rows` 를 다시 집계하면 파일의 `overall` 과 같은지 봅니다. 같은 자인지 확인하는 테스트입니다.

```bash
make test
```

`test_metrics.py` 8개가 초록이면 됩니다(`3 failed, 113 passed`).

## 2부 · LLM-as-Judge

노트북 셀 3. 루브릭은 셋이고 각각 0·1·2 입니다. 근거 일치(gold 인용문이 든 청크를 인용했나) · 수치·단위(값과 단위·기준일·절사 규칙을 모두 적었나) · 근거 밖 주장 없음. 자유 서술로 점수를 매기게 하면 같은 답변에 다른 점수가 나오므로 항목과 척도를 고정하고 한 줄 이유를 요구합니다. 채점 대상은 답할 수 있는 20문항(조항번호형 8 · 상품명조건형 6 · 표수치형 6, `judge.JUDGE_SET`)이고, 거절한 문항은 0점이 아니라 **채점 제외**입니다. 거절은 오거절률이 봅니다.

judge 점수는 일치도를 재기 전에는 숫자처럼 보이는 의견입니다. `data/golden/judge_calibration.jsonl` 에 강사 답변 17개(20문항 중 거절한 셋을 뺀 것)와 강사가 손으로 매긴 라벨이 있습니다. 같은 답변을 같은 루브릭으로 사람과 judge 가 각각 채점하면 차이는 전부 judge 의 몫입니다. 여러분 키로 돌려도 같은 답변을 채점하므로 비교가 됩니다.

## 3부 · 계산 정확도, 끝에서 끝까지

5회차 골든 테스트(`tests/test_calc_golden.py`)는 함수에 값을 직접 넣었습니다. 산식이 맞는지만 봅니다. `make calc-e2e` 는 질문을 에이전트에 넣어 검색 → 파라미터 추출 → 계산을 다 지나온 값을 봅니다. 둘의 차이가 "함수는 맞는데 추출이 틀린" 문항입니다.

맞은 것으로 치는 것은 셋입니다. 기대값과 같다(금액은 1원도 다르면 틀림) · `alternatives`(절사 규칙이 다른 정답)와 같다 · 범위형(C10)과 미답변형(C15)은 **계산하지 않은 것**. 절사 규칙으로 답이 둘인 문항(C04 총액 절사 97,890 / 건별 절사 97,884)은 어느 규칙을 썼는지 답변이 밝히면 정답이고, 안 밝히면 judge 의 "수치·단위"에서 1점입니다. `results/calc_e2e.json` 의 `how` 열이 어느 쪽으로 맞았는지, `abstain_reason` 이 왜 계산을 안 했는지입니다.

## 미답변 정확도 vs 오거절률, 적대적, 필터 정확도

노트북 셀 6 이 2×2 표를 찍습니다. 답할 수 있나 × 답했나. 오거절률은 오른쪽 위 칸, 미답변 정확도는 아래 행입니다. 한 칸을 줄이면 다른 칸이 늡니다. 재검색 상한을 올리면 오거절이 줄고 "숫자를 만듦"이 늘 수 있습니다. 어디서 멈출지가 5회차 정책 1쪽이었습니다.

적대적 5문항은 5회차 `results/adversarial.json` 그대로입니다. 통과 수를 적어 두세요.

```bash
make filter-accuracy
```

골든셋에 기대 필터가 적힌 13문항에서, 기대한 필드만 봅니다(기대는 "최소한 이 필터"라 더 뽑은 것은 세지 않습니다). 필드별(doc_type · issuer · product · generation · effective_on)로 기대 · 맞음 · 다른 값 · 놓침과 정밀도 · 재현율이 나오고, 어긋난 문항이 아래에 찍힙니다. 필터는 틀리면 **조용히 0건**이 됩니다(그러면 `relax` 가 한 단계씩 풀지만 그만큼 늦습니다). Recall 이 떨어진 문항에서 "검색이 못 찾은 것"과 "필터가 잘라 낸 것"을 가르는 숫자입니다. 노트북 셀 7 이 같은 함수입니다.

## 검증 게이트 ON / OFF (강사 시연)

같은 문서, 같은 질문, 같은 검색기(Dense). 다른 것은 2회차 인제스천뿐입니다. OFF 는 pdfplumber 로 한 번 뽑고 끝. 강사 화면에서 Recall 표와 **사라진 근거**(PDF 골든 근거 중 OFF 청크에 아예 없는 것, 전부 실손 표 페이지)를 봅니다. 근거가 없으면 어떤 검색기를 써도 못 찾습니다. 4·5회차에서 아무리 잘해도 회복되지 않는 손실입니다. 직접 돌려 보고 싶으면 수업 뒤에 `make gate-off`(임베딩 10~25분) 뒤 `make compare-gate` 입니다.

## ROI 1쪽

```bash
make roi
```

측정값(문항당 토큰 · 비용 · 재검색 비율 · 지연)과 가정값(일 500건 · 영업일 22 · 환율 1,400 · CPU 서버 월 30만 · GPU 서버 2,500만 + 연 600만 · 건당 3분 절감 · 시급 25,000)을 나눠 찍고, 월 비용 · 3년 TCO(외부 API 안 vs 내부망 GPU 안) · 절감 · 순 효과 · 손익이 뒤집히는 일 질문 수를 냅니다. 가정을 바꾸려면 `python scripts/roi.py --daily 2000 --minutes-saved 2` 처럼 돌립니다.
